# Technical Comparison: Research Literature vs Current vs Modernized ServEase

This document provides a systematic 11-aspect technical comparison between state-of-the-art research literature, current ServEase implementation, and the modernized ServEase architecture.

---

## 1. Technical Comparison Table (11 Core Aspects)

| # | System Aspect | State-of-the-Art Research Method | Current ServEase Baseline | Modernized ServEase System |
|:---:|---|---|---|---|
| **1** | **Skill Matching** | Standardized taxonomies (ESCO/O*NET), canonical synonym mapping, hierarchical skill ontology (EAAI 2026, JobMatchAI ACL 2026). | Hardcoded dictionary `SKILL_ALIASES` with 6 static domains; simple token set intersection. | Canonical skill normalization layer mapping variations (e.g. "pipe repair", "leak fix", "tap installation" $\to$ `Plumbing`) + token overlap. |
| **2** | **Semantic Matching** | Dense Transformer embeddings (e.g. BERT, SBERT, `all-MiniLM-L6-v2`) computing cosine similarity between job descriptions and worker profile bios (Singla 2024, Vyas 2026). | None. Pure string matching and substring comparison. No semantic vector space existed. | Lightweight vector space semantic similarity computing cosine similarity between concatenated job requirement text and worker bio/skills. |
| **3** | **Geographic Matching** | Spatial crowdsourcing Haversine distance with dynamic worker travel constraints and traffic-aware travel times (Miao 2024, Chen 2020). | Spherical Haversine distance calculation ($R = 6371.0\text{ km}$) with dual radius bounds ($d \le \min(r_{\text{worker}}, r_{\text{job}})$). | Preserved exact backend Haversine spherical distance calculation; normalized relative to effective radius bounds. |
| **4** | **Trust & Reputation** | Decentralized multi-dimensional reputation tracking with Bayesian smoothing and temporal decay (Rahman 2025 TinyML, Wang 2020). | Bayesian smoothed rating ($C=3.0, m=5.0$) + completion ratio + volume ramp + verification bonus. Logged to `trust_score_log`. | Preserved Bayesian trust engine; added explicit trust contribution factor into recommendation explanations. |
| **5** | **Availability** | Real-time worker scheduling constraints, time-slot overlapping, and dynamic operational availability state (Miao 2024). | Filtering on worker `availability_status` (e.g. `AVAILABLE` vs `BUSY`). | Gated retrieval filtering ensuring `BUSY` workers are pruned from active job candidate pools unless specified. |
| **6** | **Knowledge Graph** | Multi-relational Knowledge Graph modeling workers, skills, occupations, and certifications via graph embedding (Upadhyay 2021). | None. Relational SQLite/PostgreSQL schema with foreign keys. | Structured relational skill mapping + canonical taxonomy. Heavy Neo4j graph avoided due to schema simplicity and performance constraints. |
| **7** | **Explainability** | Factor-wise transparent utility attribution, natural language rationale, and feature importance breakdown (Upadhyay 2021, JobMatchAI 2026). | Monolithic scalar percentage `match_score` (e.g. `85%`) with opaque internal weighting. | Factor-level explainable decomposition: explicit breakdown of Skill Fit %, Semantic Similarity %, Distance (km), Trust Score, and Availability. |
| **8** | **Ranking Procedure** | Two-stage pipeline: First-stage candidate retrieval (filters) followed by second-stage hybrid utility reranking (JobMatchAI 2026). | Single-pass linear iteration over all workers in database with hard skill gating. | Formal two-stage architecture: Candidate Retrieval (radius + availability + category) $\to$ Multi-factor Hybrid Reranker $\to$ Top-$K$ output. |
| **9** | **Fraud / Anomaly** | Deep Isolation Forest (Xu 2023) and HF-DIF (2026) using random non-linear network representations on tabular behavior. | Unsupervised scikit-learn `IsolationForest(contamination=0.1)` on 5 features (2 hardcoded). No ground truth fraud labels. | Formalized as Unsupervised Anomaly Detection Benchmark; evaluated anomaly score distribution and documented why supervised AUC is not verifiable. |
| **10** | **Spatial Optimization** | Bi-objective Pareto optimization balancing travel distance against worker utility and platform throughput (Miao 2024). | Deterministic linear geo penalty: $\max(0.0, 1.0 - d / r_{\text{eff}})$. | Preserved geometric distance penalty with configurable trade-off coefficient tuned on validation data. |
| **11** | **Fairness / Allocation** | Fairness-aware task recommendation balancing competition and mitigating "rich-get-richer" reputation bias (ICDE 2026). | None. High-reputation workers dominate top matches, potentially starving newly onboarded workers. | Documented fairness analysis; cold-start Bayesian prior ($C=3.0, m=5.0$) partially mitigates new-worker penalty. Full fairness allocation cataloged for future work. |
